# Input

Text input field with cursor, selection, word movement (Alt+←→), clipboard support, and optional multiline/wrapping.

This example doesn't at all do it justice. The TeaUI Input component supports selection, go to beginning/end of line, go to beginning/end of document, shift-selection, move by word, undo/redo.

Even accented characters! `alt+e, e -> é`, `alt+s, s -> ş`, `alt+i, o -> ô`

## Mouse selection

- **Click** to move the cursor. Movement waits 300 ms after release to distinguish a single click from a double-click without scrolling the text between clicks. Typing or pasting during that wait commits the click immediately.
- **Double-click** the same cell to select its word. Whitespace and punctuation select their own segments, using the same word boundaries as Alt+←→.
- **Triple-click** the same cell within 300 ms of the second release to select the original logical line, including its newline when present. Wrapped rows belong to the same line, and scrolling caused by double-click selection does not change the target.
- **Click-drag** to select a range. Highlighting updates while the text stays in place; releasing commits the selection and allows the input to scroll to its endpoint.
- **Shift-click** extends the selection from its existing anchor. The endpoint previews immediately on press and follows dragging, while the text stays in place. Releasing commits the selection without a double-click delay.
- **Alt-click** toggles visible tab and newline markers without moving the cursor.

Clicks past a rendered row clamp to its last position, including the end-of-line cursor cell. Rows without a text mapping only focus the input. Dragging outside a mapped row vertically retains the last mapped endpoint; it does not auto-scroll.

## Props

| Prop          | Type                                                          | Default      | Description                                  |
| ------------- | ------------------------------------------------------------- | ------------ | -------------------------------------------- |
| `value`       | `string`                                                      | `''`         | Current text                                 |
| `placeholder` | `string`                                                      | —            | Placeholder when empty                       |
| `onChange`    | `(text: string) => void`                                      | —            | Text change callback                         |
| `onSubmit`    | `(text: string) => void`                                      | —            | Enter callback in `submit` and `mixed` modes |
| `wrap`        | `boolean`                                                     | `false`      | Wrap long lines                              |
| `multiline`   | `boolean \| 'disabled' \| 'submit' \| 'multiline' \| 'mixed'` | `'disabled'` | Newline and Enter behavior; see below        |
| `font`        | `FontFamily`                                                  | `'default'`  | Text font                                    |
| `secret`      | `boolean`                                                     | `false`      | Mask characters (for passwords); see below   |
| `isEnabled`   | `boolean`                                                     | `true`       | Dimmed and not interactive when `false`      |
| `formName`    | `string`                                                      | `''`         | The name of this value in its [Form](./form) |

## Multiline and submission modes

- `false` and `'disabled'`: the value is single-line and Enter does nothing.
- `'submit'`: the value is single-line and Enter calls `onSubmit`, then submits an ancestor [Form](./form).
- `true` and `'multiline'`: Enter inserts a newline with the current indentation. Shift+Enter inserts a plain newline.
- `'mixed'`: Shift+Enter inserts a plain newline. Enter calls `onSubmit`, then submits an ancestor Form.

Single-line modes replace initial newlines with spaces and remove pasted newlines. Multiline modes preserve pasted newlines. `wrap` is independent of these modes and only changes visual layout.

## Secret input

`secret` masks every character as `•` while `value` (and `onChange`/`onSubmit`)
still report the real text. A secret input is always single-line and never
wraps, ignores `format`, and treats its whole value as one word for Alt+←→,
Alt+Backspace, and double-click, so cursor movement can't reveal spaces or
punctuation. The placeholder is shown unmasked.

```tsx
<Input value={password} onChange={setPassword} placeholder="Password" secret />
```
