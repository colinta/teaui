# Core API (OOP)

The core API lets you build UIs by directly instantiating `View` objects. This is the foundation that the React renderer builds on.

## Hello World

```js
import {
  Screen,
  Box,
  Stack,
  Text,
  Button,
  interceptConsoleLog,
} from '@teaui/core'

interceptConsoleLog()

Screen.start(
  new Box({
    border: 'single',
    children: [
      Stack.down([
        new Text({text: 'Why is it called TeaUI?'}),
        new Button({title: 'Tell me!'}),
      ]),
    ],
  }),
)
```

## Key Concepts

### Views

Every UI element is a `View`. Views have:

- **`naturalSize(available)`** — reports preferred size given available space
- **`render(viewport)`** — draws itself into a `Viewport`
- Props like `width`, `height`, `flex` for layout

### Containers

[`Container`](/docs/components/container) extends `View` to hold children. `Box`, `Stack`, `Window`, `Accordion`, `Tabs`, and `Drawer` are containers. Use `container.add(child)`, `container.removeChild(child)`, and `view.removeFromParent()` to manage children imperatively.

### Screen

`Screen.start(rootView)` initializes the terminal and starts the render loop:

```js
import {Screen, Text} from '@teaui/core'

Screen.start(new Text({text: 'Hello!'}))
```

#### Fullscreen and inline display

Fullscreen display is the default presentation mode. It uses the alternate terminal buffer and
restores the normal buffer when the screen stops.

For an interactive view that occupies a fixed-height region in normal terminal
scrollback, you can use an `inline` mode:

```js
const [screen] = await Screen.start(new Text({text: 'Interactive output'}), {
  display: {
    mode: 'inline',
    height: 9,
    clearOnExit: true,
  },
})
```

`height` can be a positive integer or `'natural'`. With `'natural'`, TeaUI uses
the root view's `naturalSize().height`, with one row as the minimum and the
terminal's physical height as the maximum.

```js
await Screen.start(new Text({text: 'Fits\nits content'}), {
  display: {mode: 'inline', height: 'natural'},
})
```

Natural height is recalculated when the terminal is resized, so wrapped content
can grow or shrink with the available width.

`clearOnExit` defaults to `true`, which erases the reserved inline rows and
places the cursor at the start of that region. Set it to `false` to preserve the
last frame and place the shell below it.

Inline display supports keyboard, paste, focus, and supported mouse protocols
while the screen is active. It does not enter the alternate buffer. If the
terminal does not answer a standard cursor-position query, keyboard and paste
input continue to work, but mouse input is disabled because TeaUI cannot safely
translate its physical row.

TeaUI restores terminal state. Applications that install handlers for external
process signals such as `SIGTERM` remain responsible for calling `screen.stop()`
from those handlers. Calling `stop()` repeatedly is safe.

### Updating Views

Call `view.update(newProps)` to change a view's properties. This triggers a
re-render. Components use `this.invalidateRender()` and `this.invalidateSize()`
to inform the runtime that a redraw/reflow is needed.

```js
const text = new Text({text: 'Hello'})
// Later:
text.update({text: 'Updated!'})
```

### Events

Interactive views support:

- **`onClick`** — click/enter handler (Button)
- **`onChange`** — value change handler (Input, Checkbox, Slider)
- **`onSubmit`** — submit handler (Input)

Mouse events are automatic for views that render in the viewport.

## When to Use Core API

- **Object oriented code** — some people like OOP, I dunno
- **Extending TeaUI** — building custom views
- **Understanding internals** — the React API maps directly to these views

For most applications, the [React API](/docs/getting-started) is recommended.
